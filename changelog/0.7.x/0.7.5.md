# 0.7.5 — 2026-05-28

## Changed

- **`@cyanheads/mcp-ts-core`** ^0.9.6 → ^0.9.13 — picks up:
  - **`MCP_HTTP_MAX_BODY_BYTES`** — configurable inbound request-body cap (default 1 MiB); oversized requests rejected with HTTP 413 before transport allocation ([mcp-ts-core#157](https://github.com/cyanheads/mcp-ts-core/issues/157))
  - **HTTP session-init gate** — stateful HTTP mode now rejects non-`initialize` requests that arrive without `Mcp-Session-Id` with HTTP 400 ([mcp-ts-core#154](https://github.com/cyanheads/mcp-ts-core/issues/154))
  - **`httpErrorHandler`** — expected client errors (401, 403, 400, 404) now log at `warning` level instead of running the full error-handler pipeline with stack traces, reducing noise ([mcp-ts-core#158](https://github.com/cyanheads/mcp-ts-core/issues/158))
  - **`GET /mcp` keywords** — `package.json` `keywords` now surfaced on the status endpoint alongside `name`, `version`, and `description` ([mcp-ts-core#165](https://github.com/cyanheads/mcp-ts-core/issues/165))
  - `git-wrapup` and `code-simplifier` skills added; `migrate-mcp-ts-template` skill removed; `release-and-publish` artifact verification step added
  - Plugin metadata scaffold templates (`.claude-plugin/`, `.codex-plugin/`) added to the framework init command
- **`@biomejs/biome`** ^2.4.15 → ^2.4.16
- **Changelog directory scaffolded** — per-version files under `changelog/0.7.x/`; `changelog:build` and `changelog:check` scripts registered in `package.json`
- **Plugin metadata files** — `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json` populated with server metadata and install config
