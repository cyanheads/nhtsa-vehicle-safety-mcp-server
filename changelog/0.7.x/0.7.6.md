# 0.7.6 — 2026-05-30

## Changed

- **`@cyanheads/mcp-ts-core`** ^0.9.13 → ^0.9.16 — picks up `ctx.enrich` / `ctx.enrich.notice` APIs, enrichment linter rules, and framework skill updates
- **`nhtsa_search_recalls`** — `effectiveQuery` (campaign number or "make model year" string) and optional `notice` (empty-result guidance) now surface in the `enrichment` block reaching both `structuredContent` and `content[]`; empty-result text removed from `format()` (guidance now comes via `enrichment.notice`)
- **`nhtsa_search_complaints`** — same enrichment pattern: `effectiveQuery` echoes the vehicle + optional component filter; `notice` fires when no complaints are found
- **`nhtsa_search_investigations`** — `effectiveQuery` echoes applied filters (or "(all)"); `notice` fires on empty results; `output.message` field removed from structured output (value preserved via `enrichment.notice`)
- **`nhtsa_get_safety_ratings`** — NCAP coverage `notice` moved from `output.message` to `enrichment.notice`; `output.message` field removed from structured output
- **`nhtsa_lookup_vehicles`** — `effectiveQuery` echoes the operation + key args; `notice` fires on empty or out-of-bounds pages; `output.message` field removed from structured output (all four operation branches)
- **`structuredContent` field change:** `output.message` (present in `nhtsa_search_investigations`, `nhtsa_get_safety_ratings`, and `nhtsa_lookup_vehicles`) is removed from the structured output schema; the equivalent guidance now surfaces as `enrichment.notice` in both channels
