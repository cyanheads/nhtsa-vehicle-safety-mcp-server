# 0.8.0 — 2026-05-30

## Added

- **`nhtsa_search_investigations`** — `make`, `model`, and `component` are now structured filters (exact, case-insensitive substring) against the ODI flat file; previously all three were substring matches on a free-text summary field. ([#11](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/11))
- **`nhtsa_search_investigations`** — each investigation record now surfaces a `recallCampaign` field linking to the associated NHTSA recall campaign number when present in the flat file. ([#11](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/11))
- **`nhtsa_decode_vin`** — `ctx.enrich` block: `effectiveQuery` reports single vs. batch count; a `notice` surfaces when any decoded VIN carries a non-zero VPIC `errorCode`. ([#14](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/14))
- **`fflate ^0.8.3`** — streaming ZIP decompressor for the `FLAT_INV.zip` bulk file. ([#11](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/11))

## Changed

- **`nhtsa_search_recalls` (campaign path)** — replaced the binary search over the full recalls dataset (~228 s) with a direct `/recalls/campaignNumber` API call (~50 ms). ([#10](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/10), [#11](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/11))
- **`nhtsa_search_investigations`** — source switched from live `/investigations` API pagination (~121 s cold, ~42 sequential pages) to the ODI `FLAT_INV.zip` bulk flat file (~4 s cold, 24 h cache). ([#10](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/10), [#11](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/11))

## Fixed

- **`nhtsa_decode_vin`** — single-VIN path now returns `{ vehicles: [] }` when VPIC returns an empty `Results[]` (e.g. nonsense VIN); previously threw a server error (`isError: true`). ([#8](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/8))
- **`nhtsa-service` HTTP 400 handling** — `fetchJson` now parses the body on HTTP 400; if it is a result envelope (`Count`/`Message` or `count`/`message` casing with an empty `results`/`Results` array), it returns an empty success instead of throwing. Affects `nhtsa_search_recalls` and `nhtsa_search_complaints` against valid vehicles with no records on file. ([#9](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/9))
