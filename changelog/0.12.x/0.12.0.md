# 0.12.0 — 2026-11-15

## Added

- **`nhtsa_get_vehicle_safety` `investigations` section** lists every defect investigation covering the vehicle, newest opened first, matched as `nhtsa_search_investigations` matches, each row with `matchedModels` and no summary. `sectionStatus.investigations` is `unavailable` with a warning when `FLAT_INV.zip` fails or is still loading after 30 s. ([#64](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/64))
- **`notes` on recall rows** in `nhtsa_search_recalls` and `nhtsa_get_vehicle_safety`: NHTSA's recall notes as published, which hold the defect text of many campaigns received before 2000. ([#56](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/56))
- **`nhtsa_search_recalls` `includeSummary`** (default `false`) restores `summary`, `consequence`, `remedy`, and `notes` in broad rows; campaign and vehicle lookups accept it without effect. ([#60](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/60))
- **`nhtsa_lookup_vehicles` `makes` accepts `make`** and returns the makes whose name contains it, ignoring case; no match is an empty success with a notice. ([#62](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/62))
- **`nhtsa_lookup_vehicles` `dataset_models` `recalls` list**: the model names on recall-file rows for the make and model year, tagged `recalls` in `listedBy`. When the recall files fail or are still loading after 30 s, `unavailableLists` is `["recalls"]` with a notice and the other lists answer. ([#61](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/61))

## Changed

- **Breaking: `nhtsa_search_recalls` broad rows omit `summary`, `consequence`, `remedy`, and `notes` unless `includeSummary: true`.** A broad page that left text out carries a notice naming the way back. Pass `includeSummary: true`, or look the campaign up by `campaignNumber`; campaign and vehicle lookups still return all four. ([#60](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/60))
- **Empty-result notices** of `nhtsa_search_recalls` and `nhtsa_get_vehicle_safety`, and the `nhtsa_lookup_vehicles` description, name the `dataset_models` tag that marks each dataset's model names (`recalls`, `products`, `ncap`) in place of the advice to search recalls under both a series name and a base name. An empty vehicle recall lookup also routes a name tagged `recalls` that still finds nothing to a broad make + model search (2014 `CHEVEROLET SS`, which the vehicle lookup files under `SS`). ([#61](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/61))
- **`nhtsa_get_vehicle_safety` model-name notice** treats investigations like NCAP ratings: empty investigations never fire it alone. With investigations unavailable and NCAP ratings, recalls, and complaints all empty, the all-empty notice fires, naming those three sections. ([#64](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/64))
- **Headings in `content[]` hold only the ID**: NCAP `vehicleDescription` (`nhtsa_get_safety_ratings`, `nhtsa_get_vehicle_safety`) and VPIC `manufacturerName` (`manufacturer` operation) move to a labeled line. ([#59](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/59))
- **Error envelopes leave out an upstream's error body**: `data.body` and `data.responseBody` no longer carry the body of an NHTSA error response; the server log keeps it (mcp-ts-core 0.13.22).
- **Published skill `nhtsa-vehicle-safety-guide` 1.1**: search recalls under the `dataset_models` names tagged `recalls`, treat a list in `unavailableLists` as missing, and read a vehicle's investigations from `nhtsa_get_vehicle_safety`. ([#61](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/61), [#64](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/64))

## Fixed

- **`content[]` escapes every upstream string** in `nhtsa_search_complaints`, `nhtsa_search_recalls`, `nhtsa_get_vehicle_safety`, `nhtsa_get_safety_ratings`, `nhtsa_search_investigations`, and `nhtsa_lookup_vehicles`, so narratives, summaries, names, codes, and dates render as `structuredContent` carries them; a list is joined, then escaped once, since an element ending in `&amp` would take the `; ` separator's `;`. The server instructions say a backslash before punctuation in `content[]` is Markdown encoding. ([#59](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/59))
- **Notices render in `content[]` as an escaped block quote** on every tool, so caller text a notice quotes (a make, a filter value) reads back as `structuredContent.notice`. ([#59](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/59))
- **`nhtsa_search_investigations` `investigationType` accepts the five type names** (`Preliminary Evaluation` for `PE`), whole and ignoring case. A value that is neither a name nor a code in the data returns an empty success whose notice lists the accepted codes and names. ([#63](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/63))
- **An HTTP 200 with a non-JSON body** fails `ServiceUnavailable` naming the status and endpoint (was a `ValidationError` quoting the body on Node).
- **A request that never connects or outlives its 30 s timeout** fails `ServiceUnavailable` naming the endpoint (a failed connection was `-32603 "fetch failed"` on Node, and a timeout was `Timeout`).
- **A bulk-file download the connection drops partway** fails `ServiceUnavailable` with the runtime error as its cause, and caches nothing (mcp-ts-core 0.13.22).
- **An abort during a retry backoff** rejects with the caller's reason.
- **A caller abort in `nhtsa_get_vehicle_safety`** propagates instead of reading as an unavailable section.
- **`nhtsa.request_cap.clamps`** is created at module scope and binds to the meter provider on each increment, so it records once the OTel SDK starts.
