# 0.9.0 — 2026-07-30

## Changed

- **Breaking:** `nhtsa_search_investigations` `status` narrowed from a free-form string to the `"O" | "C"` enum — a lowercase or otherwise unrecognized value now fails Zod validation instead of silently matching nothing. ([#17](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/17))
- `nhtsa_search_investigations` `limit`/`offset` are now validated as non-negative integers; `limit` is capped at 25 (previously unbounded) since a single investigation summary can run several thousand characters and is rendered in full. ([#17](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/17))
- `nhtsa_search_investigations` output echoes `returned`/`offset`/`limit`, and `format()` adds next-page guidance (`Use offset=N to retrieve the next page.`) whenever more results remain. ([#18](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/18))
- README and `docs/design.md` investigations sections rewritten to match the current ODI bulk-file implementation (`FLAT_INV.zip`, 24h cache, structured make/model/component filters) — they previously described the retired `api.nhtsa.gov/investigations` endpoint and a 1h cache. ([#23](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/23))
- `src/services/nhtsa/nhtsa-service.ts` file header corrected to describe four JSON APIs plus the ODI bulk-file streaming parser (previously said five APIs); a non-null assertion and a manual falsy check were replaced with a bound-const narrowing and optional chaining.
- `@cyanheads/mcp-ts-core` `^0.10.9` → `^0.11.0`.

## Fixed

- `nhtsa_search_investigations` `format()` no longer truncates investigation summaries at 500 characters — full text is returned. ([#19](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/19))
