# 0.9.6 — 2026-09-20

## Added

- **CodeQL workflow** — static analysis runs on pushes and PRs to `main`; requires the repo's CodeQL default setup to stay off.

## Changed

- **`@cyanheads/mcp-ts-core` 0.13.6 adoption** changes what a client sees on a rejected call — inherited from the framework, not authored in this server's source. Argument rejection now returns `InvalidParams` (`-32602`) carrying `reason: "invalid_arguments"` and a `Recovery:` hint, where it previously returned an older validation code with no hint; tool error text now closes with `(reason <reason>)`; a declared parameter sent in another case style (`model_year` for `modelYear`) is honored rather than rejected, and unknown root keys are dropped before validation instead of failing the call; the upstream request URL is no longer placed on client-facing error data.
- **HTTP session posture** is now declared `stateless` in code ([#41](https://github.com/cyanheads/nhtsa-vehicle-safety-mcp-server/issues/41)) — a `bunx` or from-source run matches the container and the hosted deployment: no `Mcp-Session-Id` is issued and the server card publishes `sessionMode: stateless`.
- **Development skills** moved from `skills/` to `framework-skills/`, so installing this server as a Claude Code or Codex plugin no longer hands its development skills to the installing agent.
- **Issue templates** route framework vs. server bugs, add a private security-advisory link, and drop the stale label-creation note.

## Fixed

- **`manifest.json`'s `MCP_LOG_LEVEL`** now routes through the declared `user_config` option instead of a stale literal, so a user's chosen log level reaches the server.
